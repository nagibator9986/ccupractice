# Подписание через eGov mobile (QR-код / кнопка «Открыть eGov mobile»)

Подписант может поставить ЭЦП **без NCALayer и без файла ключа** — в приложении
**eGov mobile**: открыл ссылку → отсканировал QR (на компьютере) или нажал кнопку
(на телефоне) → подтвердил PIN-кодом или биометрией. Страница договора сама
увидит результат и перейдёт в «Договор подписан».

> **Состояние: реализовано, выключено по умолчанию.** Сервер реализован по
> официальной спецификации «QR/Кросс подписание в приложении eGov Mobile»
> (API №1 / API №2) и проверен имитацией приложения (настоящий сертификат,
> настоящая проверка подписи) и в браузере. На **реальном** eGov mobile не
> проверялось: eGov пускает к QR-подписанию только зарегистрированные домены.

## Как это работает

```
Страница подписания  ──POST /api/signing/public/<token>/egov/session──▶  сервер создаёт сессию
        │                                                              (QR = «mobileSign:<API №1>», ссылки mgovsign.page.link)
        │ показывает QR / кнопку и раз в 2 с спрашивает статус
        ▼
eGov mobile (телефон)
  1. GET  /api/egov/<secret>            API №1: что подписываем, кто, срок, где взять документ
  2. GET  /api/egov/<secret>/documents  API №2: PDF договора (Bearer-токен сессии)
  3. подписывает (CMS_WITH_DATA, штамп времени НУЦ РК)
  4. PUT  /api/egov/<secret>/documents  API №2: возвращает подпись
        ▼
сервер проверяет подпись → 200 «success» (или 403 с понятным текстом) → страница обновляется
```

Сессия одноразовая и живёт 10 минут (`EGOV_SESSION_TTL_MIN`). Секрет в адресе и
Bearer-токен — по 256 бит; PDF «пришит» к сессии по SHA-256, поэтому если договор
пересформировали между сканом и подтверждением, подпись **не принимается**.

## Что нужно, чтобы включить

1. **Публичный HTTPS-адрес** (Railway его даёт). Приложение не работает с `http`.
2. **Регистрация информационной системы у eGov.** По официальной документации
   eGov mobile обращается только к адресам из списка доверенных: колледж
   регистрируется на портале **Smart Bridge** (sb.egov.kz) и подаёт заявку на
   услугу QR-подписания, указав домен платформы. Сроки рассмотрения могут быть
   долгими — начинайте заранее. Документацию («Документация по QR/Кросс
   подписанию в приложении eGov Mobile») выдают там же.
   *Альтернатива без регистрации:* сервис-посредник **SIGEX** (sigex.kz) даёт
   QR-подписание через свой API, но документы идут через стороннего оператора и
   это **другая интеграция** (в платформе не реализована).
3. Переменные окружения на Railway:

   | Переменная | Значение |
   | --- | --- |
   | `EGOV_SIGN_ENABLED` | `1` |
   | `EGOV_SESSION_TTL_MIN` | `10` (необязательно, 2–60) |

   После этого на странице подписания появится выбор «eGov mobile / NCALayer».
   Пока `EGOV_SIGN_ENABLED` не задан, ничего не меняется — подписывают через NCALayer.
4. **Проверка подписей ГОСТ.** Сертификаты в eGov mobile обычно национальные
   (ГОСТ). Включите NCANode (`docs/NCANODE_SETUP.md`), иначе такие подписи
   получат уровень «ГОСТ: привязка подтверждена», а не «Проверено НУЦ РК».

## Что именно подписывается — важно для юристов

- **eGov mobile** показывает подписанту только PDF (и текст/XML), поэтому
  подписывается **PDF-версия** договора. **NCALayer** по-прежнему подписывает
  **DOCX**. Способ и файл записаны у каждой подписи (`channel`, `payload_format`)
  и видны в карточке договора, на странице проверки `/verify/<код>` и в листе
  подписей.
- Целостность проверяется **по каждой подписи против «её» файла**: DOCX-подписи —
  против DOCX, eGov-подписи — против PDF. Любая замена архивного файла видна на
  странице проверки.
- Подписи сторон в одном договоре могут быть сделаны над разными представлениями
  (DOCX и PDF) одного и того же документа. Юридически это стоит согласовать с
  юристом колледжа; если нужна единая версия — подписывать всем PDF (для
  NCALayer это отдельное небольшое изменение).
- Подпись принимается, только если внутри CMS лежат **ровно наши байты PDF**
  (`CMS_WITH_DATA`): так привязка к документу проверяется по содержимому для
  любых алгоритмов и отсекается подпись «не того» документа (известная проблема
  одной из версий Android — подпись над base64-текстом).

## Проверка и отладка

- Тесты: `cd backend && .venv/bin/python -m unittest tests.test_egov_sign -v`
  (имитируют приложение полностью: API №1 → №2 → подпись → PUT, плюс отказы).
- Вручную: на странице подписания выберите eGov mobile → в ответе
  `POST …/egov/session` есть `qr_content` (`mobileSign:https://…/api/egov/<secret>`).
  Адрес после `mobileSign:` можно открыть `curl` — это API №1.
- Локальный тест с телефоном: публичный HTTPS-туннель (ngrok и т. п.) и
  заголовок `X-Public-Origin` (его ставит сама страница) — адреса в QR строятся
  из адреса, с которого открыта страница подписания.
- Если приложение пишет ошибку про домен — домен не добавлен в доверенные у eGov
  (шаг 2). Тексты ошибок сервера приложение показывает как есть
  (`{"message": "..."}`, языки ru/kk/en по `Accept-Language`).

## Что не проверено

- Работа с настоящим eGov mobile (нужен зарегистрированный домен и устройство).
- eGov Business (подпись руководителя организации корпоративным ключом):
  спецификация описывает eGov Mobile; поддержку Business уточните у НИТ.
- Формат ответа на нестандартные версии приложения: сервер строгий — любая
  подпись, не прошедшая проверку, возвращает 403 с причиной, и сессия закрывается
  (нужен новый QR).
