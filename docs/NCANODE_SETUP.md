# Юридически-полная проверка ЭЦП (NCANode) — настройка на Railway

Когда платформа заменяет **бумажные договоры**, электронная подпись должна
проверяться по стандарту РК: сама ГОСТ/RSA-подпись + цепочка сертификата до
корня **НУЦ РК** + статус отзыва (**OCSP/CRL**). Библиотека `cryptography` не
умеет ГОСТ, поэтому полную проверку делает **NCANode** — сервис на официальном
SDK KalkanCrypt. CCU PRACTICUM отправляет ему CMS и принимает подпись только при
положительном вердикте.

Без `NCANODE_URL` система работает на локальной проверке: RSA/ECDSA — полностью,
ГОСТ — принимается с привязкой к документу, но **без** криптопроверки/цепочки/
отзыва. Для боевой эксплуатации настройте NCANode по шагам ниже.

## ⚠️ Важно про библиотеки KalkanCrypt

NCANode проверяет ГОСТ через проприетарные библиотеки **KalkanCrypt** НУЦ РК.
Из исходников NCANode они удалены (лицензия), поэтому **публичный образ
`malikzh/ncanode:latest` может НЕ содержать их** — тогда проверка ГОСТ вернёт
ошибку. Поэтому подключайте NCANode **в безопасном порядке** (см. ниже): сперва
`NCANODE_STRICT=0`, проверяете реальную ГОСТ-подпись, и только если появился
бейдж «Проверено НУЦ РК» — включаете строгий режим. KalkanCrypt-библиотеки у вас
уже есть — в этом репозитории, папка `SDK 2.0/Java/` (если понадобится свой
образ — см. раздел «Если публичный образ не проверяет ГОСТ»).

## Шаги на Railway

1. **Добавьте сервис NCANode.** В проекте Railway → **New → Deploy a Docker
   Image**. Впишите имя образа и **нажмите Enter** (НЕ кликайте по синей
   ссылке-подсказке `hub.docker.com/...` — она лишь открывает сайт Docker Hub):
   ```
   malikzh/ncanode:latest
   ```
   (репозиторий: https://github.com/malikzh/NCANode). NCANode слушает порт
   **14579**. Желательно подключить Volume к `/app/cache`.

2. **Дайте сервису приватный адрес.** Railway автоматически выдаёт внутренний
   домен вида `ncanode.railway.internal`. Внешний домен NCANode **не нужен** —
   к нему ходит только наш backend.

3. **Пропишите переменные нашему backend-сервису** (Settings → Variables).
   На старте — **нестрогий режим**, чтобы проверить, что образ реально умеет ГОСТ:
   | Переменная | Значение (старт) |
   |---|---|
   | `NCANODE_URL` | `http://ncanode.railway.internal:14579` |
   | `NCANODE_STRICT` | `0` — пока проверяем (не ломать подписание, если NCANode не умеет ГОСТ) |
   | `NCANODE_VERIFY_OCSP` | `1` |
   | `NCANODE_VERIFY_CRL` | `0` |

   Точное имя внутреннего хоста — в NCANode → Settings → Networking →
   *Private Networking*.

4. **Передеплойте backend** (Railway сделает это сам после изменения переменных).

5. **Проверьте на реальной ГОСТ-подписи.** Подпишите тестовый договор и
   откройте карточку подписи у админа:
   - Бейдж **«Проверено НУЦ РК»** → образ работает, KalkanCrypt на месте.
     Теперь можно ставить `NCANODE_STRICT=1` (боевой режим: непроверенные/
     отозванные подписи отклоняются).
   - Предупреждение «Полная проверка НУЦ РК временно недоступна» или ошибка →
     публичный образ **не содержит KalkanCrypt**. Перейдите к разделу ниже.

## Если публичный образ не проверяет ГОСТ

Тогда нужен **свой образ NCANode со встроенными библиотеками KalkanCrypt** (они
у вас есть — `SDK 2.0/Java/`). Порядок:
1. Клонировать NCANode, положить `knca_provider_jce_kalkan-*.jar`,
   `kalkancrypt-*.jar`, `kalkancrypt-xmldsig-*.jar` из SDK в папку `lib/`.
2. Собрать: `./gradlew build` → получится `NCANode.jar` с библиотеками внутри.
3. Собрать Docker-образ (`docker build -t <ваш-реестр>/ncanode .`), запушить в
   реестр (Docker Hub / GHCR), и на Railway деплоить уже **ваш** образ.

Это разовая DevOps-задача. Я могу подготовить точные команды/Dockerfile под ваш
SDK — скажите, когда дойдём до этого шага.

## Поведение при сбое NCANode

- `NCANODE_STRICT=1` (рекомендуется для прода): если NCANode недоступен, подпись
  **не принимается** — пользователь видит «Сервис проверки подписи (НУЦ РК)
  недоступен… повторите позже». Это не даёт принять непроверенную подпись.
- `NCANODE_STRICT=0`: мягкий откат на локальную проверку с пометкой
  «Полная проверка НУЦ РК временно недоступна» (удобно на этапе обкатки).

## Локальная проверка (Docker Compose)

```yaml
services:
  ncanode:
    image: malikzh/ncanode:latest
    ports: ["14579:14579"]
```
Затем `NCANODE_URL=http://127.0.0.1:14579` в `backend/.env`.

## Замечания по соответствию (production)

- **NCANode сам обновляет** корневые сертификаты и CRL НУЦ РК — отдельной
  настройки обычно не требуется; следите за обновлениями образа.
- **Метка времени (TSP).** Для строгого доказательства момента подписи можно
  включить получение TSP-штампа; это отдельный шаг (НУЦ РК предоставляет
  TSP-сервис) — закладывается на уровне NCANode.
- **Персональные данные** студентов/родителей — храните по Закону РК «О
  персональных данных»: согласие (документ согласия формируется платформой),
  ограничение доступа (роли уже есть), резервное копирование БД и архива
  (Railway Postgres backups + Volume на `/app/backend/{archive,uploads}`).
