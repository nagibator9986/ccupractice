# CCU PRACTICUM — Краткая инструкция для сотрудников колледжа

## 1. Вход в систему
- Откройте `http://<адрес-сервера>:5173` (или порт, указанный администратором).
- Введите логин и пароль. По умолчанию для администратора: `admin@ccu.kz / admin123`.
- В правом нижнем углу боковой панели всегда отображается текущий пользователь.

## 2. Заполнение реестра партнёров
1. Перейдите в раздел **Партнёры**.
2. Нажмите **«+ Добавить партнёра»**.
3. Заполните минимум: название организации (обязательно), БИН, адрес, ФИО директора, должность, основание (Устав/Доверенность №…), банковские реквизиты, количество мест, специальность.
4. Сохраните.

> Поиск работает в реальном времени по названию, БИН, контактному лицу и специальности.

## 3. Студенты: загрузка группы из Excel

Самый быстрый путь — загрузить список группы файлом. Раздел **Группы** (или **Студенты**) →
кнопка **«Загрузить из Excel»**.

### 3.1. Какой файл нужен
Подойдёт любой из вариантов:

1. **Шаблон колледжа** — кнопка **«Скачать шаблон Excel»** в окне загрузки. Заголовки уже расставлены,
   обязательные колонки (ФИО, ИИН, Группа) выделены цветом, предприятие и специальность выбираются
   из выпадающих списков.
2. **Свой файл** со столбцами «ФИО», «ИИН», «Группа» и любыми из: специальность, курс, телефон,
   дата рождения, предприятие, даты практики, руководители. Заголовки распознаются автоматически
   («Ф.И.О.», «Тел.», «Практика с»… тоже подойдут). Нераспознанные столбцы можно сопоставить вручную
   на шаге проверки.
3. **Список группы в том виде, как он ведётся**: сверху блок «Курс / Специальность / Группа / Куратор»,
   ниже — столбец с ФИО (без заголовка и даже без ИИН). Система возьмёт группу, специальность,
   код специальности и курс из этого блока.

Группа определяется так: столбец «Группа» → блок «Группа:» над таблицей → название листа
(один лист = одна группа). Можно также указать группу вручную для всех студентов файла.
Форматы: **.xlsx** и **.csv** (старый .xls сначала сохраните как .xlsx).

### 3.2. Как проходит загрузка
1. **Файл.** Выберите файл, при необходимости задайте группу, режим для уже существующих студентов
   и сразу **предприятие и сроки практики для всей загрузки**.
2. **Проверка.** Ничего ещё не сохранено. Система показывает, сколько студентов будет добавлено,
   обновлено, пропущено и какие строки содержат ошибки (с причиной и номером строки). Ошибочные строки
   можно скачать в CSV. Нужны ли новые группы, видно сразу.
3. **Готово.** После подтверждения студенты сохраняются; сразу предлагается следующий шаг —
   назначить практику или оформить договоры.

**Как система ищет студента, который уже есть в базе:** по ИИН, а если ИИН нет — по ФИО (и группе).
Дубли не создаются. Режимы:

| Режим | Что делает |
| --- | --- |
| **Дополнить пустые поля** (по умолчанию) | Заполняет только пустое, ничего не затирает |
| **Только новые** | Существующих студентов не трогает |
| **Обновить данными из файла** | Заменяет значения данными из файла (ИИН не меняется) |

Список без ИИН загружается нормально. Позже загрузите файл с ИИН в режиме «Дополнить пустые поля» —
студенты найдутся по ФИО, ИИН допишется. **Для договора ИИН обязателен.**

> Предприятие должно быть заранее добавлено в раздел **Партнёры**. Если в файле указано неизвестное
> предприятие, система предупредит и не будет создавать его сама.

Если загрузили не то — выделите студентов в разделе **Студенты** и нажмите «Удалить»
(студенты, у которых уже есть договор, удалить нельзя — система их пропустит и назовёт).

### 3.3. Группы — центр управления практикой
Раздел **Группы** показывает каждую группу карточкой: сколько студентов, у скольких назначено
предприятие и заданы сроки, как продвигаются договоры, и подсказывает **следующий шаг**.
Из карточки доступны: назначить практику, оформить договоры, открыть студентов/договоры группы,
выгрузить группу в Excel.

### 3.4. Назначить предприятие и сроки практики сразу всей группе
Карточка группы (или выделенные студенты) → **«Назначить практику»**: предприятие, даты,
руководители, вид практики. Можно менять только пустые поля. Если у предприятия не хватает мест,
система предупредит.

### 3.5. Ручное добавление и редактирование
**Студенты** → **«Добавить студента»**. Обязательное поле — ФИО; для договора также нужны ИИН и сроки
практики. Паспортные данные удобно заполнить сразу — они подставляются в договор.
Отметка **«Грантник (госзаказ)»** открывает доступ к LMS-договору (см. ниже).

### 3.6. LMS-договор (подключение к Caspian Digital)

LMS-договор оформляется **только на студента с отметкой «Грантник»** и только один
незавершённый договор на студента.

1. Отметьте студента как грантника (в карточке или галочкой в таблице).
2. В строке студента нажмите **«Создать LMS-договор»** — откроется мастер с уже
   выбранным студентом. Либо: раздел **LMS-договоры** → **«+ Новый LMS-договор»**.
3. Проверьте номер и дату, при необходимости укажите приказ о зачислении, и сохраните.

**Почему студента может не быть в списке мастера:**

- у него не стоит отметка «Грантник» — включите её в карточке;
- у него **уже есть незавершённый LMS-договор** — второй оформить нельзя. Номер
  действующего договора виден в колонке **«LMS-договор»** реестра студентов; кнопка
  в строке при этом меняется на **«Открыть LMS-договор»**.

**Почему карточка студента не удаляется:** пока у студента есть LMS-договор (в любом
статусе, включая «Завершён»), удалить карточку нельзя — иначе договор остался бы без
владельца. Система назовёт номер договора и предложит открыть его. Удалите сначала
договор (кнопка «Удалить договор» в его карточке), затем карточку студента.

> Пока LMS-договор не завершён, снять отметку «Грантник» тоже нельзя — соответствующий
> флажок блокируется, а сервер отклонит попытку.

**Если в договоре указан не тот студент.** ФИО и ИИН внутри договора — это *снимок*
данных на момент оформления, его можно править (для исправления опечаток). Сам договор
при этом остаётся привязан к карточке студента, с которой он был создан. Если ФИО
переписали на другого человека, договор «уедет»: в реестре студентов он всё ещё
числится за прежним студентом, а открывается на другое имя.

Система теперь показывает это явно:

- в реестре студентов под номером договора появляется красная пометка
  **«⚠ в договоре: <другое ФИО>»**;
- на странице договора сверху видно **«Привязан к студенту: …»**, а при расхождении —
  предупреждение с объяснением.

Как починить: на странице договора нажмите **«Перепривязать»**, найдите нужного студента
и выберите его. Система спросит, переписать ли ФИО/ИИН в договоре по карточке студента.
Привязать можно только к студенту с отметкой «Грантник» и без другого незавершённого
договора. Если нужного человека нет в реестре — сначала заведите его на вкладке
«Студенты».

## 4. Оформление договоров

### 4.1. Всей группой сразу (рекомендуется)
**Группы** → карточка группы → **«Создать договоры»** (или выделите студентов в разделе «Студенты»).
Мастер покажет заранее, что произойдёт:

- **будет создано N договоров** (номера ПП-ГГГГ-001… присваиваются автоматически, по алфавиту);
- **пропущено**: нет предприятия; уже есть договор в этом году; **не хватает данных** (например, ИИН) —
  с перечнем недостающего и ссылкой на карточку студента;
- предупреждения: у предприятия не хватает мест или истёк срок договора с ним.

После подтверждения система создаёт договоры, **формирует DOCX/PDF по одному (с индикатором хода)** и —
если отмечено — сразу выпускает ссылки на подпись предприятию и студенту. В конце можно скачать
**Excel со ссылками** и готовыми текстами сообщений для рассылки.

### 4.2. Один договор
**Договоры практики** → **«Новый договор»**: выберите предприятие и студента. Система сразу покажет,
чего не хватает в данных, и предупредит о дубле (тот же студент + предприятие + год).
В карточке договора кнопка **«Сформировать договор»** собирает данные колледжа, предприятия и студента
и сохраняет DOCX (и PDF, если на сервере есть LibreOffice).

> Если не заполнены обязательные данные (ИИН студента, сроки практики, БИН и реквизиты предприятия,
> ФИО директора колледжа), система не даст сформировать договор, пока вы не исправите это или
> явно не подтвердите «сформировать всё равно».

## 5. Подписание электронной подписью (ЭЦП)

### 5.1. Что делает администратор
В карточке договора блок **«Следующий шаг»** всегда подсказывает, что делать:
сформировать → отправить на подпись → ждём подписи → завершить.

- **Отправить на подпись** создаёт персональные ссылки для предприятия и студента. Ссылку можно
  скопировать, отправить в WhatsApp (если указан телефон — сразу нужному человеку), Telegram или почтой.
  Система сама ничего не рассылает — ссылку передаёте вы.
- **Продлить** — срок ссылки (30 дней) увеличивается, а сама ссылка остаётся прежней.
  **Новая ссылка** — старая перестаёт работать. **Отозвать** — закрывает ссылку.
- Колледж подписывает прямо из карточки кнопкой **«Подписать здесь»** (нужен NCALayer).
- Для многих договоров: в списке выделите договоры → **«Отправить на подпись»** или **«Ссылки (Excel)»**.

### 5.2. Что видит подписант
Подписанту не нужен логин. По ссылке он видит договор (PDF прямо на странице), ставит отметку
«Я ознакомился с договором» и нажимает **«Подписать ЭЦП»**. Нужны установленный и запущенный
**NCALayer** (https://pki.gov.kz/ncalayer/) и ключ ЭЦП. После подписи страница подтверждает результат
и даёт скачать договор. Идентификаторы (ИИН/БИН) на публичной странице показаны частично.

**Через eGov mobile (если включено в колледже).** На странице подписания вместо NCALayer можно выбрать
«eGov mobile»: на компьютере появится QR-код — отсканируйте его приложением eGov mobile на телефоне; на телефоне
нажмите «Открыть eGov mobile». Приложение покажет договор — подтвердите подпись PIN-кодом или биометрией.
Ключ ЭЦП и NCALayer не нужны; страница сама обновится. Подробности для администратора:
`docs/EGOV_MOBILE_SETUP.md`.

Когда подписали все три стороны, статус договора становится «Подписан».

> Бумажный вариант: можно загрузить скан подписанного договора (PDF/JPG/PNG) — статус сменится на «Скан загружен».

## 6. Управление статусами
В карточке договора статус меняется в блоке «Статус» (только администратор, предлагаются лишь допустимые переходы):

- **Черновик** — создан, но не сформирован файл
- **Сформирован** — DOCX/PDF готов
- **Отправлен партнёру** — администратор пометил, что договор отправлен
- **Подписан** — все три стороны подписали ЭЦП
- **Скан загружен** — загружен скан бумажного варианта
- **Завершён** — договор закрыт

### 6.1. Удаление договора
Кнопка «Удалить договор» находится в «Опасной зоне» карточки. Нужно ввести номер договора.
Если у договора есть подписи или скан, система предупредит отдельно: удаление уничтожит электронные
подписи и файлы безвозвратно.

## 7. Архив
- Раздел **Архив** показывает все договоры, для которых уже сформирован файл.
- Режим «Дерево» отображает иерархию: **Год → Партнёр → Договоры** (как в ТЗ).
- Каждый файл можно скачать в DOCX или PDF; реестр договоров выгружается в Excel.

## 8. Настройки шаблона
- Только администратор.
- Раздел **Настройки шаблона**: реквизиты колледжа подставляются во все договоры.
- Можно загрузить собственный `.docx` шаблон с переменными `docxtpl` (`{{ partner.organization_name }}` и др. — список доступных переменных прямо в интерфейсе).

## 9. Резервное копирование данных
- БД находится в `backend/instance/ccu.db` — можно копировать любым удобным способом (rsync, cron-задача).
- Сформированные договоры хранятся в `backend/archive/` — рекомендуется ежедневно синхронизировать на внешнее хранилище.
- Сканы — в `backend/uploads/`.

## 10. Безопасный режим
- Пользователи с ролью **Просмотр** могут только листать реестры, фильтровать, скачивать файлы. Они не могут добавлять, изменять или удалять записи и формировать договоры.
- Все пароли хранятся в виде bcrypt-хешей.

## Поддержка
По вопросам обращаться к администратору сервера колледжа.
