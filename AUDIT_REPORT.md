# CCU PRACTICUM — отчёт о профессиональном аудите и исправлении ошибок

**Дата:** 2026-06-21
**Объект:** трёхсторонняя платформа подписания договоров практики (Flask + React/Vite, NCALayer ЭЦП)
**Объём кода:** ~6 400 строк (backend ~3 100, frontend ~3 300)

## Резюме

Проведён полный аудит проекта силами 12 параллельных проверяющих агентов по
направлениям: безопасность, корректность логики, целостность данных, гонки,
контракт API frontend↔backend, обработка ошибок, конфигурация и деплой.

- **56** «сырых» находок → после состязательной перепроверки по фактическому коду
  подтверждено **39**, отклонено **17** (ложные/несуществующие).
- После дедупликации — **33 уникальные проблемы** + **1** дополнительно выявленный
  разрыв авторизации (неаутентифицированная отдача файлов).
- **Исправлены все** подтверждённые проблемы. Изменено 29 файлов, добавлены
  полноценные миграции БД.

## Важно при деплое на существующую БД

Начальная миграция (`backend/migrations/versions/…_initial_schema.py`) включает
уникальные констрейнты на `students.iin` и `partners.bin`. На **чистой** БД всё
применяется автоматически. На **уже наполненной** Postgres-БД:

1. Сначала устранить возможные дубликаты ИИН/БИН.
2. Затем применить миграцию: `flask db upgrade` (или дать приложению сделать это
   на старте — это уже встроено).

Аналогично, если в существующей БД были задвоены строки `college_settings`
(из-за прежней гонки сидинга), нужна разовая чистка до фиксации singleton `id=1`.

## Методология

Аудит выполнен многоагентным оркестратором (12 направлений-ревьюеров →
состязательная перепроверка каждой находки по фактическому коду → синтез с
дедупликацией). Каждое исправление затем верифицировано компиляцией, запуском
приложения на чистой БД и функциональными тестами через Flask test client;
frontend — продакшен-сборкой Vite.
